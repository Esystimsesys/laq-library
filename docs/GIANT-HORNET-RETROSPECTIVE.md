## 振り返りとフィードバック

| 起きたこと | 原因 | 次回への反映 |
|---|---|---|
| 写真から仮置きした頭、腹、尾、羽を繰り返し修正した | 写真で見えない接続・板数を含む初回候補だった | 見える形と推定接続を区別し、番号・使用口・空き口・左右への適用を部品IDで固定してから直す |
| 手順統合後に全パーツがバラバラになった | 全パーツが新規となる手順で、分解グループ処理が個別表示へフォールバックした | 過去に作ったパーツがない場合も明示した分解区分を使う |
| 修正後は体全体が一塊になった | unitsの所有範囲を、ユーザーがいう分解のまとまりと同一視した | 手順の区切り・部品の所有・分解の区分を別に扱い、既存の体内部の区分も残す |
| スライダーを離す側へ動かさず「まとまりを保持」と報告した | 組み上がった表示だけを確認した | 分解変更では0と100だけを実際に操作し、同じ塊の相対位置を確認する。全手順・全画面幅の反復で補わない |
| 前後の羽を組む順番と取り付け順番を整理し直した | 片側ごとに作成と取り付けを交互に並べていた | 左右を先に組む準備手順と、体へ取り付ける手順を分ける。羽は準備時に個別分解、取り付け時に一体でよい |
| 完成形だけ旧分解のまま残った | 完成形がunitsから独自に区分を作っていた | 完成形も準備手順の分解定義に追従させ、共通描画を直した際は完成形を一度確認する |

レビュー途中で確認を絞るよう求められた。限定した確認へ切り替えたが、誤った前提で修正して再確認を招いた点が問題だった。検査を増やすことより、変更前の区分を正しく読むことを優先する。保存時の版照合と対象外の形状・接続の比較は、人の編集を守るために有効だった。

再発防止を [制作ワークフロー](AI-3D-WORKFLOW.md#手順統合と分解表示の変更) へ反映した。
