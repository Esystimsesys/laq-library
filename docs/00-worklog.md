## 1. 依頼と決めたこと

依頼は「LaQの作り方を一覧にして、詳細を確認できるライブラリアプリ。検索・お気に入り・作成済み管理つき。
作り方の一覧サイトがあるか調査して、あればそこから持ってくる」。公式サイトとして
<https://www.laq.co.jp/gallery/> が提示された。UI は**子どもが使う前提**で、
楽しさと分かりやすさを踏まえ、AIっぽい見た目にしないこと。

計画段階で確認した方針は次のとおり。

| 項目 | 決定 | 補足 |
|---|---|---|
| データ範囲 | まず公式のみ。**他ソースを後から足せる作り**にする | ぷりまつラボ等の取り込みは今回やらない |
| 形態 | PWA + GitHub Pages | `boardgame-scorer` と同じ土台 |
| 画像・PDF | **公式URLを直接参照**（複製・再配布しない） | オフラインでは未取得の図が出ない前提 |
| カテゴリ | キーワードで自動タグ付け | 公式にはレベルしか分類が無いため |

## 2. データ源の調査

### 見つけたもの

公式ギャラリーは無限スクロールで、HTML には作品が 1 件も埋まっていなかった。
`/assets/js/InfiniteLoading_gallery.js` を読むと、**`https://www.laq.co.jp/assets/json/gallery.json`**
を読んでいることが分かった。これが全作品の一覧そのもので、245 件・
`id / title / exp / level_code / level / permalink / thumbnail` を持つ。

つまり**一覧のスクレイピングは不要**で、詳細ページだけ読めばよい構成になった。

詳細ページ（例 `/gallery/005171/index.php`）は Movable Type 生成でマークアップが安定しており、
完成写真・説明文・つくり方の図（複数枚）・つくり方PDF の URL が機械的に取れた。

### 確認した事実

- 内訳は 初級 82 / 中級 123 / 上級 40
- `laq.co.jp` に robots.txt は無い（404）
- 画像にホットリンク保護は無い（Referer 偽装・無 Referer とも 200）。CORS ヘッダは無いが `<img>` 表示には不要
- 手順画像は 245 件すべてに存在。PDF は 244 件（「原始人と骨付き肉」のみ無し）
- 参照される画像 URL はユニークで 943 件（サムネ＋完成写真＋手順の図）

### 採らなかった案

[ぷりまつラボ](https://purimatu.com/katatizukan/)（ポケモン 400 件超）は件数では魅力的だが、
個人ブログの HTML スクレイピングになり構造が不安定で、負荷への配慮も別途必要。
公式で完結する構成を優先し、スキーマだけ後から受け入れられる形にした。

## 3. 作ったもの

### 取り込み

- `scripts/fetch-gallery.mjs` — `gallery.json` + 各詳細ページ → `src/data/sources/laq-official.json`
  - 直列 + 300ms 間隔、HTML は `.cache/html/` に保存
  - 実行のたびに集計・欠損・**前回 JSON との差分**を出す
- `scripts/tag-rules.mjs` — 作品名（当たらなければ説明文）からカテゴリを推定する辞書

### カテゴリ設計

子どもが探しそうな順に 14 種：きょうりゅう / どうぶつ / とり / むし / うみのいきもの /
キャラクター・くうそう / のりもの / たべもの / はな・しょくぶつ / ぎょうじ・きせつ /
こもの・アクセサリー / あそび・ゲーム / たてもの・けしき / へいめん。

245 件すべてを目視で確認し、**実際に踏んだ誤爆を潰した**。日本語の部分一致は誤爆しやすい。

| 誤爆 | 原因 | 対処 |
|---|---|---|
| トラック → どうぶつ | 「とらっく」に「とら」 | `/とら(?!っく\|んす\|いく)/` |
| トライク → どうぶつ | 同上 | 同上 |
| クリスマス* → どうぶつ | 「くりすます」に「りす」 | 「りす」を辞書から削除（リスの作品は無い） |
| ポリスヘリコプター → どうぶつ | 同上 | 同上 |
| サッカーボール → のりもの | 「さっかー」に「かー」 | `/(?<!さっ)かー(?!ねーしょん)/` |
| カーネーション → のりもの | 同上 | 同上 |
| ハシビロコウとカワセミ → むし | 「かわせみ」に「せみ」 | `/(?<!わ)せみ/` |
| 鎧兜（よろいかぶと） → うみのいきもの | 「よろいかぶと」に「いか」 | 「いか」「たこ」を削除 |
| ガソリンスタンド → こもの | 「すたんど」 | 「すたんど」を削除し具体語だけ残す |
| ミニレーサー イエロー → たてもの | 「いえろー」に「いえ」 | `/いえ(?!ろー)/` |
| さくらもち → はな | 「さくら」 | `/さくら(?!もち)/` |
| ハナメガネ → はな | 「はな」 | `/はな(?!めがね)/` |

結果、**未分類（その他）0 件**。

### 画面

- 下タブ **さがす / おきにいり / つくった / せってい** ＋ 作品詳細
- 検索はひらがな↔カタカナ、全角↔半角、中黒・空白を吸収する自作正規化（ライブラリ追加なし）
- 記録は `localStorage` の `laq-library:v1` のみ

### デザインの方針

「AIっぽくしない」ために、**やらないこと**を先に決めた。

- グラデーション背景・ぼかした影・ガラス風の半透明を使わない
- 絵文字をUIの主役にしない（アイコンは 24×24・線幅 2.2 で統一した自作SVG）
- 汎用SaaSの見た目（Inter系・紫アクセント・角丸8px）に寄せない

代わりに「紙のずかんにカラフルなパーツのシールを貼った」方向にした。
丸ゴシック（Zen Maru Gothic）、うすい方眼の背景、輪郭線＋**ずらしたハード影**、
色は LaQ の基本パーツ（赤・青・黄・緑）から取る。アイコンも同じ発想で、
四角と三角のパーツを組んだ絵にした（`scripts/make_icons.py` / Pillow で生成）。

## 4. 実機での検証

headless Chrome を CDP（`/tmp/cdp.mjs` に最小クライアントを自作）で操作して確認した。
最初 `--headless --screenshot --force-device-scale-factor=2` で撮ったときは右側が見切れており
横あふれを疑ったが、`Emulation.setDeviceMetricsOverride` で正しくエミュレートして計測すると
`scrollWidth === clientWidth === 390` で**あふれていなかった**。旧 headless のスケール指定の問題だった。

確認できたこと。

- 検索「きょうりゅう」→ 11 件、作品を開く → ★と✓を押す → `localStorage` に保存される
- オフライン: 一覧・検索・記録が動作、直リンク `/model/...` も開く、一度見た図はキャッシュから表示
- 画像ホストを遮断した状態: 壊れ画像 0 件、しましまのプレースホルダに置換
- 存在しない ID が記録に残っていても、一覧から黙って除外される

途中で見つけて直した表示の不具合。

- つくり方の手順が `<ol>` なのに `ul` にしかリセットを当てておらず、既定の番号と自作の番号バッジが二重に出ていた
- 図の拡大オーバーレイの背景が薄く、細い線が読みにくかった（0.88 → 0.95）
- 歯車アイコンが太陽に見えていた（歯の形を描く実装に変更）
- オフラインで未取得の画像が壊れアイコンになっていた → `RemoteImage` を作り、
  読めなかったらしましまのプレースホルダ＋文言に置換

## 8. Codex による全体レビューと反映（2026-09-07）

`codex exec --sandbox read-only` で全体レビューを依頼し、指摘を一つずつ自分で確認してから直した。

### 重大

| 指摘 | 確認 | 対応 |
|---|---|---|
| 複数タブで記録を上書きして失う | `AppStore` に `storage` リスナーが無く、後から保存したタブが起動時の状態ごと上書きすることを確認 | `data/external` アクションを足し、別タブの書き込みを取り込む。`saveState` は内容が同じなら書かないので、取り込み側が書き戻してタブ間で反応し合うことはない |

### レビューをきっかけに見つけた別の不具合

Codex が追加した Playwright の e2e を実際に走らせたら **4 件すべて落ちた**。原因は
`playwright.config.ts` の webServer が `npm run preview` を使っていたこと。
`base` は `vite.config.ts` が `GITHUB_PAGES` を見て決めるので、**ビルド時だけ**
`GITHUB_PAGES=true` にしても preview 側は `base: '/'` で立ち上がり、
`index.html` が指す `/laq-library/assets/*.js` が 404 になって真っ白になる。

`preview:pages` スクリプトを足して webServer をそちらに向けたら 4 件とも通った。
**GitHub Pages と同じサブパス配信での動作確認が、これまで一度も成立していなかった**ことになる。
デプロイ前に気づけたのは、レビュー結果を鵜呑みにせず実際にテストを走らせたため。

### CI

`deploy.yml` に `npm run test:e2e`（chromium）を追加。あわせて
`actions/configure-pages` に `enablement: true` を付け、Pages 未設定のリポジトリでも
初回デプロイで有効化されるようにした。

  現在の e2e は `serviceWorkers: 'block'` なので PWA の要が自動テスト対象外という指摘は妥当だが、
  別プロジェクト構成が要るので分ける。オフライン動作自体は CDP で手動確認済み（4節）。
