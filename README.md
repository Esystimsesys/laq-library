# LaQライブラリ (laq-library)

LaQ の作り方 **1,472 件**（公式ギャラリー 245 + ぷりまつラボ 1,227）を、
**さがす / おきにいり / つくったきろく** の 3 つの目的で引けるようにしたスマホ向け PWA。

公式サイトはレベル（初級・中級・上級）でしか絞り込めず、無限スクロールで毎回頭から探すことになる。
また「どれを作ったか」を残す場所がない。このアプリはその 2 つを埋めるための索引で、
つくり方の図そのものは公式サイトのものをそのまま表示する。

- 作品名・説明・カテゴリの**全文検索**（ひらがな／カタカナ、全角／半角のゆれを吸収）
- **むずかしさ**（かんたん / ふつう / むずかしい）と**なかま**（きょうりゅう・のりもの…14 種）で絞り込み
- **★おきにいり**と**✓つくった**（作った日・ひとことメモ付き）を端末内に記録
- **手元の LaQ の冊子にある作品を、自分で登録できる**（冊子名・ページ・写真つき）。
  取り込んだ作品と同じ一覧・検索・記録の仕組みに乗る
- オフラインでも一覧・検索・記録は動く（一度見た図はキャッシュから開ける）

## つかう

```sh
npm install
npm run dev        # http://localhost:5173
```

| コマンド | すること |
|---|---|
| `npm run dev` | 開発サーバ |
| `npm run build` | 型チェック + 本番ビルド |
| `npm run build:pages` | GitHub Pages 用ビルド（サブパス配信 + 404.html） |
| `npm run preview` | ビルド結果の確認 |
| `npm run preview:pages` | GitHub Pages 用ビルドの確認（`build:pages` の結果を見るときはこちら。`preview` だとサブパスが合わず真っ白になる） |
| `npm run test:e2e` | Playwright（実ブラウザでの画面確認） |
| `npm run lint` | oxlint |

| `npm run fetch:gallery` | 公式ギャラリーから作品データを取り込み直す |
| `npm run fetch:purimatu` | ぷりまつラボから作品データを取り込み直す |

## 作品データの取り込み

`src/data/sources/*.json` は取り込みスクリプトの生成物。手で編集しない。

| ソース | 件数 | つくり方 | 生成コマンド |
|---|---|---|---|
| LaQ公式 つくり方ギャラリー | 245 | 手順の図 + PDF をアプリ内で表示 | `npm run fetch:gallery` |
| ぷりまつラボ（ポケモン） | 1,227 | 完成写真だけ持ち、手順は本家の記事へリンク | `npm run fetch:purimatu` |

### LaQ公式 つくり方ギャラリー

`src/data/sources/laq-official.json` は `npm run fetch:gallery` が生成する。

取り込み元は公式サイトの 2 つ。

1. `https://www.laq.co.jp/assets/json/gallery.json` — 全作品の一覧
   （ギャラリーの無限スクロールが読んでいる実体）
2. 各作品の詳細ページ — 説明文・完成写真・つくり方の図・PDF の URL

詳細ページは直列 + 300ms 間隔で読み、`.cache/html/` に残す。キャッシュは **30 日** で
古くなったとみなして取り直す（公式は同じ作品 ID のまま説明文や画像を差し替えることがある）。
`--refresh` を付けると全部取り直す。

実行すると集計と欠損、そして**前回の JSON との差分**を出す。公式が作品を足したら
ここに `+ 作品名` が出るので、それを見て `src/data/data.test.ts` の件数を更新する。

取りこぼしがあると **終了コード 1** で終わる（気づかずに `git add` しないため）。
また、完成写真・つくり方の図・PDF のどれかが全体の 2 割超で取れなかった場合は
「公式ページの構造が変わった可能性がある」と報告する。cheerio はセレクタが外れても
エラーにならないので、この見張りが無いと静かに空データになる。

```
── 集計 ─────────────────────────
総数: 245
レベル: intermediate=123 beginner=82 advanced=40
カテゴリ:
  きょうりゅう　　　　　　 11
  ...
── 欠損 ─────────────────────────
title なし: 0
thumbnail なし: 0
手順画像なし: 0
```

### カテゴリの自動付与

公式データにはレベルしか分類が無いので、`scripts/tag-rules.mjs` の**キーワード辞書**で
作品名（当たらなければ説明文）から推定している。推定なので誤爆する。

- 取り込みスクリプトが「その他」に落ちた作品名を出すので、辞書に語を足す
- 「トラック → とら → どうぶつ」のような誤爆は、正規表現の除外か `OVERRIDES` で直す
- 実際に踏んだ誤分類は `scripts/tag-rules.test.mjs` に再発防止のテストとして残してある
- 同じテストに「取り込み済み 245 件のカテゴリが、いまの辞書の結果と一致する」という
  照合がある。辞書に語を足して関係ない作品の分類が変わると、その作品名が出て落ちる。
  意図した変更なら `npm run fetch:gallery` で JSON を作り直す

### ぷりまつラボ

`src/data/sources/purimatu.json` は `npm run fetch:purimatu` が生成する。

記事ページを 1 件ずつ読むと 1,200 回以上のアクセスになるので、**WordPress の REST API**
（`/wp-json/wp/v2/posts?per_page=100`）を使う。本文まで含めて **13 リクエスト**で全記事を取れる。
個人ブログなので、この差は大きい。

- 記事タイトルが「〜の作り方 / つくり方 / つくりかた」のものだけを作品として扱う
  （商品レビューやまとめ記事が混ざっているため）。表記も `LaQ` / `Laq` が混在する
- 難易度は本文の「むずかしさ：★★★」から読む（★4 は上級と同じ扱い。23 件は記載なし）
- **手順の写真は取り込まない。** このブログの手順は写真のあいだの日本語の説明とセットで
  意味を持つので、写真だけ並べても読めない。本文を持ってくるのは複製にあたる。
  加えて、全件ぶんの URL を同梱すると JSON が 2.5MB になる（完成写真だけなら 700KB）
- 作品名に「ラキュー」など飾りが残っていたら、タイトルの取り出しが外れているとみなして報告する

### 別のサイトを足すとき

作品データはソースを跨いだ形（`src/data/types.ts` の `Model`）にそろえてある。追加は 3 手順。

1. `SourceId` に union を足す
2. 取り込みスクリプトを書いて `src/data/sources/<id>.json` を出す
3. `src/data/index.ts` の `SOURCE_FILES` に足す

画面側にソースごとの分岐は書かない。難易度の無いソースがあり得るので `level` は `null` を、
手順の図が無いソースがあり得るので `stepImages` は空配列を許している。

出典表記（権利者名・リンクの文言）は作品ごとではなく**ソースごとに 1 度だけ**持ち、
画面は `sourceOf(model)` で引く。1,000 件を超えると、同じ文字列を全件に持たせるだけで
同梱データが目に見えて重くなるため。

## 画像と著作権について

**作品の写真・つくり方の図・PDF は、それぞれの出典（ヨシリツ株式会社／ぷりまつラボ）の著作物。**
このアプリはそれらを複製せず、出典サイトの URL を参照して表示するだけ。
リポジトリにも `dist` にも画像は含まれない。
「画像の URL が、その作品の出典サイトと同じホストを指すこと」をテストで固定してある。

- 作品の詳細画面には必ず出典と公式ページへのリンクを置く
- 取り込みスクリプトは公開ページを 1 件ずつ穏当な間隔で読むだけで、
  認証や anti-bot の回避はしない

作品情報の出典:

- [LaQ つくり方ギャラリー](https://www.laq.co.jp/gallery/)（ヨシリツ株式会社）
- [ぷりまつラボ](https://purimatu.com/)

## 運用で気をつけること

- **公式の更新を自動で検知する仕組みは無い。** 手で `npm run fetch:gallery` を回して
  差分レポートを見る運用。CI では取り込みを走らせていない（生成物はコミット済み）
- **つくり方 PDF はオフラインキャッシュの対象外。** 1 件 1MB 超で全体では重すぎるため、
  画像（サムネ・完成写真・手順の図、計 943 件）だけを端末に残している
- 画像は公式サーバから直接読むので、**公開すると閲覧者のぶんだけ公式へリクエストが飛ぶ。**
  一度読んだものは Service Worker のキャッシュから出るので定常的な負荷は下がるが、
  このアプリは個人〜身内で使う規模を前提にしている

## 手元の冊子から自分で登録する

商品に付いてくる冊子の作品を、アプリ内で登録できる（「さがす」画面の
「＋ 手元の さっしから じぶんで とうろく」）。作品名・冊子名・ページ・むずかしさ・
なかま・メモ・写真を持ち、`source: 'my-booklet'` として取り込んだ作品と同じ形にそろえる
（`src/lib/myModels.ts`）。おかげで一覧・検索・おきにいり・つくった の仕組みが
そのまま使え、画面側に「自分の作品かどうか」の分岐が散らばらない。

**冊子の図は取り込まない。** 冊子は商品に付いてくる著作物で、ページの内容を
アプリに入れることはしない。持つのは「どの冊子の何ページに何があるか」という索引と、
自分で撮った完成写真だけ。**このデータは端末の中だけにあり、リポジトリには入らない。**

写真は IndexedDB（`laq-library-photos`）に Blob で入れる。`localStorage` は文字列しか
入らず容量も 5MB 前後なので、写真を base64 で入れると数枚で他の記録ごと保存できなくなる。
保存前に長辺 800px の JPEG に縮める。

## 記録の保存先

`localStorage` の `laq-library:v1` だけ（写真は上記のとおり IndexedDB）。
サーバへは何も送らない。

```jsonc
{
  "version": 1,
  "favorites": ["laq-official:005171"],
  "made": { "laq-official:005171": { "madeAt": "2026-09-01", "note": "はじめて つくれた" } },
  "booklets": [
    {
      "id": "my-booklet:<uuid>",
      "title": "きょうりゅうロボ",
      "booklet": "ベーシック401",
      "page": "12",
      "level": "intermediate",
      "categories": ["きょうりゅう"],
      "note": "",
      "hasPhoto": true,
      "createdAt": "2026-09-07T00:00:00.000Z"
    }
  ]
}
```

作品の ID は公式の作品 ID 由来で、取り込み直しても変わらない。データを更新しても記録は残る。
公式から消えた作品が記録に残っていた場合は、一覧に出さず黙って捨てる。

「せってい」から JSON で書き出し・読み込みができる（端末の引っ越し用）。
書き出しには自分で撮った写真も data URL で混ぜる。混ぜないと、端末を替えたときに
写真だけ置き去りになるため。写真の枚数だけファイルは大きくなる。
取り出せなかった写真があれば枚数を知らせる（黙って落とすと、写真の無いファイルを
「ほぞんしました」と言ってしまう）。読み込みは記録を丸ごと置き換えるので、
古い写真を先に捨ててから入れる。

## 配信

`main` に push すると GitHub Actions が `npm run build:pages` して GitHub Pages に出す。
クライアント側ルーティングなので、`dist/404.html` に `index.html` をコピーして
直リンク（`/model/...`）でも開けるようにしている。
